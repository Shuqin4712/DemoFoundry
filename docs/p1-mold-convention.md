# P1 · 模具约定（草案）

> 状态：**草稿，待认可**（2026-10-03）
> 来源：zeedemo 的 `product-ui-rebuild` skill（截图 → 量成 JSON → 组件 → 数值对表）、`shared/assets/canvas-ui/` 的实际用法、`zui.py` 的标记写法。
> 这份定的是**模具里的东西长什么样、放在哪、怎么证明它对**；怎么一步步建模具是 `demofoundry-mold` skill 的事（P4）。
> 发布前译成英文，放进 skill 的 references。

## 1. 模具是什么

模具 = 一个产品的界面组件库，加上证明它和产品一致的证据与质检页。它住在用户仓库的 `demofoundry/mold/`，每做一集按需补组件，越做越厚。

生成器只通过模具使用产品界面：**合成里不内联重画任何产品界面**（zeedemo SERIES-WORKFLOW 阶段 4 的规则）。

## 2. 目录

```
demofoundry/mold/
  mold.json                 模具清单：前缀、单位来源、组件表、各组件质检状态（见 §8）
  theme/
    tokens.css              颜色、字体变量；每个值注明采样来源
    fonts/                  产品字体（确认授权；不能分发的写进 .gitignore，记在 README）
  components/
    <组件>/
      <组件>.css            样式；每个常数带「实测值 + 来源」注释
      <组件>.html           标记模板（见 §4）
      <组件>.json           元数据：尺寸、状态、锚点、插槽、来源（见 §5、§6）
  evidence/
    <组件>/<状态>.png       截图证据，PNG @2x，不压缩、不后期
    recordings/<名>.mp4     录屏证据；旁边 _index/ 是 recording 工具的状态索引
    figma/                  Figma 导出（PNG @2x + 节点信息）
    source/                 从产品源码摘出的 CSS / token 文件，注明仓库和提交
  qc/
    proof.html              数值对照页：参考图并排 / 叠加 / 差分 + 实测对表
    gallery.html            总览页：组件按真实用法裸摆，看默认状态
    results.json            最近一次质检结果（机器可读，见 §8）
  intro-outro/              片头片尾的主题参数（片头片尾的机制在引擎里）
  README.md                 给人看的完成度表 + 已知未解分歧
```

## 3. 单位与缩放

| 约定 | 内容 | 为什么 |
| --- | --- | --- |
| 单位 | **产品的 1x 逻辑像素**。retina 截图在 2x 原图上量，最后除以 2；录屏按「录屏像素 ÷ 缩放比」换算，缩放比记在证据旁边 | 量得准；Figma 1x、浏览器 CSS px 是同一种单位 |
| 世界坐标 | 合成里摆组件用的坐标 = 1x 逻辑像素 | 和 zeedemo 一致（「Figma 1x px = 世界坐标」） |
| 缩放变量 | 每个模具一个前缀 `<p>`，所有尺寸写成 `calc(<实测>px * var(--<p>-u))`，圆角、边框宽也不例外 | 组件能在任意尺寸下复用；镜头推近时不糊 |
| 字间距 | 用 `em` | `px` 不随缩放变 |
| 缩放契约 | `--<p>-u` 从 1 改到 1.5，所有被规定的常数严格等比 | 质检项之一（§7） |

画幅（16:9、以后的 9:16）和分辨率（1080p、4K）由镜头和渲染决定，和模具无关。

## 4. 组件

**一个组件只描述「长什么样」**：不带位置、不带出现时机、不带动画起始态。

### CSS

- 类名全部带模具前缀：`.<p>-<组件>`、`.<p>-<组件>__<部位>`。
- 选择器加作用域，不污染合成里的其他元素。从产品源码或 Figma 复刻 HTML 搬来的 CSS，每个选择器都要加。
- 边框用 `outline` + 负 `outline-offset`，画在盒内。
- flex 子项（图标、按钮）一律 `flex: 0 0 auto`。
- 从已有场景提取样式时，剥掉 `left / top / width / height` 绝对值和 `opacity: 0` 这类场景实例状态。
- 每个常数旁注释「实测值 + 来源证据」。刻意偏离产品的值注明「刻意偏离，非实测」和原因。

### 标记模板 `<组件>.html`

- 一段 HTML，带具名插槽，例如 `{{label}}`、`{{badge}}`、`{{slot:inner}}`（嵌入别的组件或媒体）。
- **不带 JS。** 产品里的点击、rAF、`performance.now()` 违反渲染确定性；交互状态一律用 class 表达，由时间轴切换。
- 子元素 id 规则：`<实例 id>-<部位>`（来自 `zui.py` 的做法）。动画按这个 id 找元素，不靠 DOM 结构猜。
- 列表一类可变结构（菜单项、历史记录）：模板里给一行的样子，插槽传一组数据。复杂到模板表达不了的组件，允许旁边放一个 `<组件>.py` 自己拼标记 —— 这是例外，元数据里注明。

### 状态

- 状态用 class：`is-<状态>`（`is-hover`、`is-open`、`is-selected`、`is-busy`）。
- 每个状态至少一张证据；没有证据的状态不能出现在成片里。
- 组件元数据列出全部状态；生成器用到列表外的状态时直接报错。

## 5. 锚点

**锚点 = 组件上有名字的点**：按钮中心、菜单第 i 行中心、连线出入口、文字插入点。光标、连线、高亮都挂在锚点上，不在生成器里写死坐标。

- 坐标系：相对组件根节点左上角，1x 逻辑像素，随 `--<p>-u` 缩放。
- 写在 `<组件>.json` 的 `anchors` 里：

  ```json
  "anchors": {
    "variation-button": { "x": 108, "y": 21, "source": "evidence/nodebar/default.png" },
    "menu-item": { "x": 68, "y": "72 + 44*i", "source": "evidence/nodebar/menu-open.png" }
  }
  ```

  带索引的锚点（第 i 行）写成含 `i` 的表达式。

- 生成器里用 `anchor(实例, '名字', i=…)` 取世界坐标；引擎负责加上实例位置、乘缩放、经镜头换算成屏幕坐标。
- **锚点也要质检**：对照页在真实 DOM 里量出锚点对应元素的中心，和元数据比，容差同 §7。这样组件改了样式、锚点没跟着改，质检会报。

zeedemo 里对应的是 `zui.py` 的 `NB_VAR`、`VMENU_ITEM`、`BAR_GEN` 这类常数，散落在 Python 里、没有质检。

## 6. 元数据 `<组件>.json`

```json
{
  "name": "nodebar",
  "size": { "w": 433, "h": 46 },
  "states": ["default", "menu-open", "tooltip"],
  "slots": ["label"],
  "anchors": { "...": "见 §5" },
  "allow_overlap": true,
  "evidence": ["evidence/nodebar/default.png", "evidence/recordings/edit-flow.mp4@4.5s"],
  "source_kind": "screenshot",
  "markup": "template"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `size` | 是 | 默认尺寸；可变尺寸的组件写默认值并在 CSS 里说明 |
| `states` | 是 | 全部状态；第一个是默认态 |
| `anchors` | 用到才填 | 见 §5 |
| `allow_overlap` | 否 | 盖住别的元素是产品真实行为时为 `true`，生成时自动加 `data-layout-ignore`，免得 HyperFrames `check` 报文字重叠 |
| `evidence` | 是 | 每个状态至少一条；录屏写 `文件@秒` |
| `source_kind` | 是 | `code` / `figma` / `recording` / `screenshot`，决定归一化走哪条路（§6.1） |
| `markup` | 是 | `template`，或 `python`（例外，见 §4） |

### 6.1 四种证据怎么归一化

不管从哪来，最后都落成 §4 的组件 + §5 的锚点 + §7 的质检。

| 来源 | 做法 |
| --- | --- |
| 产品源码 | 摘出相关 CSS 和设计 token 放进 `evidence/source/`；搬进组件时加作用域、换成缩放写法、去掉 JS；仍然要截图证据做画面差分 |
| Figma | 有链接 + 只读 token：用上游 `hyperframes figma component / asset / tokens`；有现成复刻 HTML：直接归一化。数值优先取 Figma 属性，同时导出 PNG @2x 做对照 |
| 录屏 | `recording` 工具建状态索引、按框裁出证据图；交互过程（出现、展开、拖拽）的时序只能从录屏来 |
| 截图 | `ref_profile` 批量量成 JSON，读 JSON、不读图；量不到的特征写一次性脚本 |

## 7. 质检

沿用 zeedemo 的标准（决策记录 2026-10-03：±0.3px + 画面差分，自主模式也跑）。

| 项 | 标准 |
| --- | --- |
| 数值对表 | 每个组件、每个状态一个标本；逐项实测和参考值比，**容差 ±0.3 逻辑像素** |
| 必测项 | 卡片 / 容器：宽、高、圆角、边框色与宽、面色；文字：字号（墨迹高）、字重（笔画宽）、字间距、换行；图标：按类型的宽高；小控件：尺寸、宽高比、居中偏差；连线：线宽、颜色、端点方向；媒体：四边内缩、圆角裁切；锚点：位置 |
| 画面差分 | 参考图与组件并排、叠加、差分，给人看 |
| 缩放契约 | `--<p>-u` 1 → 1.5 严格等比 |
| 总览页 | 默认状态下看不见、被压扁、飘走的组件在这里暴露 |
| 语义确认 | 测量测不出「这是不是同一个元素、何时出现」，把总览页给人看，专门问语义 |

**不过就停。** 对表没过的就写没过；两种测法互相矛盾就保留成失败项，写进 README 的「已知未解分歧」，不调参压过去。自主模式下质检没过，停下来报告。

## 8. 状态记录

`mold.json` 是机器读的清单，工作台和自主模式都靠它判断模具能不能用：

```json
{
  "prefix": "acme",
  "unit": "1x logical px",
  "components": {
    "nodebar": { "qc": "pass", "checked": 81, "failed": 0, "at": "2026-10-03" },
    "model-pop": { "qc": "fail", "checked": 24, "failed": 1, "at": "2026-10-03", "note": "见 README 已知分歧 #2" }
  }
}
```

`qc` 取值：`pass` / `fail` / `unchecked`。`qc/results.json` 存最近一次质检的逐项结果。`README.md` 是同一份信息给人看的版本。

## 9. 按集增量

- 每集的讲稿阶段列出本集用到的组件和状态。
- 做一集时先对照 `mold.json`：缺组件、缺状态、或 `qc` 不是 `pass`，转去建模具（共创模式下先问人）。
- 第一集只建本集用到的组件。

## 待定（需要你拍板）

1. **标记模板用什么写法？** 草案是「HTML + 具名插槽，复杂组件允许例外用 Python」。另一种是全部用 Python 函数（zeedemo `zui.py` 的做法），表达力强，但用户的模具里就有代码了，和「用户最好不碰代码」有点冲突。我倾向草案的写法。
2. **前缀谁定？** 草案是初始化时从产品名生成一个短前缀（如 `acme`），写进 `mold.json`，之后不改。
3. **产品字体能不能进仓库？** 很多商用字体不允许再分发。草案是：能分发的放 `theme/fonts/`，不能的进 `.gitignore`，在 README 里写怎么取得。
